# Locked Long-Term Product Decisions (Stage 4A Polish Updated)

Index: [[SLBot]] | Architecture: [[Architecture]]

> [!NOTE]
> Stage 4A Polish updated key product specifications for branding, errors, staff uniqueness, offer command shape, and roster presentation.

## 1. Global Bot Permissions Role & Recovery

- The user-facing configuration option and internal setting is **`bot_permissions`** (`botPermissionsRoleId`). The old `league_admin` terminology is deprecated and removed.
- A user has global bot permissions when either:
  - they hold the configured `bot_permissions` role, or
  - they have the Discord **Administrator** permission.
- **Discord Administrator Recovery & Bootstrap**: Administrator permission provides initial bootstrap setup and emergency recovery access.
- Club staff positions (TM, ATM, PM) grant authority over their team's offer operations, but **DO NOT** grant global bot setup or administrative permissions.

## 2. Dual-Channel and Staff Channel Matrix

- **Dual-Channel Commands** (`/health`, `/team list`, `/staff list`, `/roster`, `/limit view`, `/offer`): Allowed in both the configured **Bot Commands Channel** and **Staff Channel**.
- **Staff-Only Commands** (`/setup league`, `/setup channels`, `/setup roles`, `/setup view`, `/team add`, `/team edit`, `/team remove`, `/limit default`, `/limit team`, `/limit reset`, `/staff appoint`, `/staff remove`, `/debugreset`): Restricted strictly to the **Staff Channel**.
- **Bootstrap Exception**: Before the staff channel or `bot_permissions` role exists, a Discord Administrator may run setup commands in any current channel. Once configured, setup commands must use the staff channel.

## 3. Embed-Only Response Architecture & Ephemeral Errors

- **Embed-Only Rule**: Every response generated by the bot MUST be a Discord embed (public successes, ephemeral successes, setup output, lists, rosters, limits, offer acknowledgements, and error messages). Plain text command outputs are prohibited.
- **Title Formatting & Actor Line**: All success titles start with `✅`, all error titles start with `❌`. Every administrative mutation embed features an explicit actor line at the bottom (`Configured by`, `Added by`, `Appointed by`, `Removed by`).
- **Specific Domain Conflict Errors**: Database and domain conflicts (duplicate team role, duplicate team name, duplicate short name, staff already appointed, position occupied) produce clear ephemeral red error embeds identifying the conflicting record or team name.

## 4. Global Staff Uniqueness Rule

- A user may hold **only one active club staff appointment across the entire league** (guild).
- Pre-flight checks reject attempts to appoint an already-appointed user (`❌ Staff member already appointed`).
- Position slot uniqueness (1 TM, 1 ATM, 1 PM per team) is also pre-flight enforced (`❌ Position already occupied`).

## 5. Team Branding with Custom & Unicode Emojis

- `/team add` requires a team emoji; `/team edit` allows optional emoji updates.
- External `logo_url` inputs are removed from commands.
- Supports server custom emojis (`<:name:emojiId>`, `<a:name:emojiId>`) validated against current guild emojis via Option A (`hasGuildEmoji`), and standard Unicode emojis (`⚽`, `🦁`).
- Single-team embeds use derived custom emoji CDN or Twemoji URLs as thumbnails.

## 6. Flattened `/offer` Command

- Final command shape: `/offer player:<user>` (no `create` subcommand, no `team` option).
- Source/destination club is **automatically derived** from the caller's active staff appointment (TM, ATM, PM).
- Callers without an active staff appointment are rejected ephemerally with `❌ Staff appointment required`.

## 7. Roster Reference Layout

- Roster view follows exact visual reference layout:
  - Author: `<Guild Name>`
  - Title: `<EMOJI> <TEAM NAME> Roster`
  - Thumbnail: Team logo from emoji
  - Fields: `📊 Roster Count`, `👑 Franchise Owner(s)`, `👔 General Manager(s)`, `🧠 Head Coach(es)`, `📋 Assistant Coach(es): Future Role — Not Available Yet`, `──────── Players ────────`, `🏃 Players`
  - Footer: `Roster for <Guild Name>`

## 8. `/team remove` vs `/disband` Distinction

- **`/team remove`**: Soft deactivation (`active = false`). Preserves all historical records in SQLite.
- **`/disband`**: Reserved for future complete franchise shutdown workflow.

## 9. Development `/debugreset` Command

- Enabled via `SLBOT_ENABLE_DEBUG_COMMANDS=true`.
- Discord Administrator only, Staff channel only.
- Safety prompt with confirmation buttons (60s timeout, user-gated).
- Performs transactional, FK-safe data reset for current server.
