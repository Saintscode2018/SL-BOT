# Locked Long-Term Product Decisions (Stage 4A Hotfix Corrected)

Index: [[SLBot]] | Architecture: [[Architecture]]

> [!NOTE]
> Stage 4A Hotfix corrected several initial product assumptions following live Discord testing. The decisions below supersede original Stage 4A specifications.

## 1. Global Bot Permissions Role & Recovery

- The user-facing configuration option and internal setting is **`bot_permissions`** (`botPermissionsRoleId`). The old `league_admin` terminology is deprecated and removed.
- A user has global bot permissions when either:
  - they hold the configured `bot_permissions` role, or
  - they have the Discord **Administrator** permission.
- **Discord Administrator Recovery & Bootstrap**: Administrator permission provides initial bootstrap setup and emergency recovery access.
- Club staff positions (TM, ATM, PM) grant authority over their team's offer operations, but **DO NOT** grant global bot setup or administrative permissions.

## 2. Dual-Channel and Staff Channel Matrix

- **Dual-Channel Commands** (`/health`, `/team list`, `/staff list`, `/roster`, `/limit view`, `/offer create`): Allowed in both the configured **Bot Commands Channel** and **Staff Channel**.
- **Staff-Only Commands** (`/setup league`, `/setup channels`, `/setup roles`, `/setup view`, `/team add`, `/team edit`, `/team remove`, `/limit default`, `/limit team`, `/limit reset`, `/staff appoint`, `/staff remove`): Restricted strictly to the **Staff Channel**.
- **Bootstrap Exception**: Before the staff channel or `bot_permissions` role exists, a Discord Administrator may run setup commands in any current channel. Once configured, setup commands must use the staff channel.

## 3. Embed-Only Response Architecture & Ephemeral Errors

- **Embed-Only Rule**: Every response generated by the bot MUST be a Discord embed (public successes, ephemeral successes, setup output, lists, rosters, limits, offer acknowledgements, and error messages). Plain text command outputs are prohibited.
- **Ephemeral Error Embeds**: All handled errors produce visible ephemeral error embeds detailing clear user-facing messages.
- Stack traces remain strictly in server application logs and are never exposed to Discord users.
- Errors remain ephemeral even when the triggering command would produce a public embed.

## 4. Custom Emoji Team Branding

- Custom Discord emojis (`<:name:emojiId>` or `<a:name:emojiId>`) are the primary visible team branding logo.
- External image hosting is not required for normal team creation.
- Custom emojis are validated and converted to Discord CDN URLs (`https://cdn.discordapp.com/emojis/EMOJI_ID.png` or `.gif`).
- Single-team embeds use the derived custom emoji CDN URL as the embed thumbnail.
- Multi-team lists display custom emoji mentions inline beside team names.

## 5. Command Naming: `/setup league`

- Renamed `/setup guild` to **`/setup league`**.
- The user-facing command tree no longer contains `/setup guild`. Database schema retains internal guild IDs where required by Discord and Prisma.

## 6. Staff Structure & Squad Limits

- Each club may appoint up to 1 Team Manager, 1 Assistant Manager, and 1 Player Manager.
- Staff appointments do not count toward player squad limits unless holding an active `PLAYER` membership.
- Guild-wide default squad limit is **17**. Effective limit resolution:
  $$\text{Effective Limit} = \text{squadLimitOverride} \mathbin{??} \text{defaultSquadLimit}$$

## 7. Private Contract Offers

- Offers are delivered exclusively via private DMs to the target player with persistent buttons.
- Command execution outputs a public embed acknowledgement in channel without revealing sensitive internal details.

## 8. `/team remove` vs `/disband` Distinction

- **`/team remove`**: Performs a safe soft deactivation of an active team (`active = false`). Preserves all historical records in SQLite (memberships, staff appointments, offers, transactions, and audit logs). Output embed is titled `Team Removed` and clarifies that historical data is preserved.
- **`/disband`**: Reserved for the future complete franchise shutdown workflow (which may handle player releases, role removals, and franchise dissolution in Stage 4B+).
